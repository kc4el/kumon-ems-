## Bugs/dead controls found (with selectors)

1. **Dead LIVE/DEMO badge — `setApiMode` targets a node that does not exist.** `dashboard.js:48-56` writes `#apiModeBadge`, but no `apiModeBadge` string occurs anywhere in `pages/dashboard.html`. The function null-guards, so every `setApiMode('live'/'demo')` call silently does nothing. Tour step 2 promises "the little badge tells you whether the numbers are fresh" (`dashboard.js:344`) — there is no badge.
2. **Dead activity feed — `loadActivityFeed` targets a node that does not exist.** `dashboard.js:324-336` writes `#activityFeedList`; no `activityFeedList`/`activityFeed` id exists in `pages/dashboard.html` (only the CSS rules at `main.css:3869-3888` remain — cf. commits `d65fe55`, `7d00e43`, `fa1427b` which moved/removed the hero feed markup). The loader returns early on every page; tour step 2's "The Today box shows the latest goings-on" (`dashboard.js:344`) describes UI that is not in the DOM.
3. **Dead attendance loader — `#attendanceTableBody` missing.** `loadAttendanceView` (`dashboard.js:1568-1599`) early-returns; the daily punch-table `<tbody>` has no id (`dashboard.html:1396`). Static demo rows render forever with no LIVE/DEMO disclosure; tour step 6's day-arrow claim is only the static markup.
4. **Dead shift-roster loader — `#shiftRosterTableBody` missing.** `loadShiftRosterView` + `refreshShiftConflictBadges` (`dashboard.js:1601-1651`) early-return; no such tbody in `dashboard.html` (tbodys enumerated at lines 289, 332, 1396, 1447, 1551, 1715, 2014, 2106, 2208, 2412, 2485, 2690, 2802, 3096, 3326 — none with that id). The roster board is DOM-only demo; leave-clash flags never query the API.
5. **Dead payroll loader — `#payrollRunsTableBody` + `#payrollLiveWrap` missing.** `loadPayrollView` (`dashboard.js:1653-1694`) early-returns; neither id exists in `dashboard.html`. `switchView`'s payroll branch (`dashboard.js:167-175`) can therefore never show (additionally, `viewBreadcrumbs` has `reports` but the sidebar has no Reports/Payroll link — `dashboard.html:30-75` lists only dashboard/employees/attendance/claims/messages/logs — so those views are reachable only via `switchView` calls, landing on the generic `view-placeholder` "Production Module Active" card, `dashboard.html:3347-3357`).
6. **Leave register has no loader at all.** `#leaveRegisterTableBody` exists (`dashboard.html:2014`) but no function in `dashboard.js` ever fetches leaves into it; rows are static badges (Accepted/Rejected/Pending). There are no approve/reject controls in that table — tour step 8's "you can approve or say no … from the same list" (`dashboard.js:350`) is false.
7. **Duplicate `showToast` definitions — `type` is silently dropped.** `function showToast(message)` (`dashboard.js:841`) is hoisted, so the `typeof window.showToast !== 'function'` fallback (`dashboard.js:1429-1449`, the only variant that colors `type === 'error'` red) never installs. All ~40 `showToast(msg, 'error')` calls render identically to info toasts. Fix: fold the `type` styling into the primary definition and delete the dead fallback.
8. **`escapeHtml(undefined)` throws in `confirmAddStaff`.** `dashboard.js:757-762` passes `initials`/`name`/`jobTitle` from `select.value.split('|')` unwrapped; a malformed option value (or future empty part) throws `Cannot read properties of undefined`. Not exploitable today (options are static, `dashboard.html:1785+`), but wrap with `String(... || '')` like the loaders do.
9. **Hardcoded demo constants presented as live.** `setShiftDateToday` pins `2026-06-18` (`dashboard.js:706-713`, comment "Demo live date"); `handleShiftDateChange` labels the board `Allocation (demo) for …` (`dashboard.js:684`) — that parenthetical is the one honest label in the roster flow, but the follow-up toast `Roster updated for …` (`dashboard.js:686`) implies a persisted write that never happens (see honesty). `filterAuditLogs` always reports `of 1,482 logged admin events` (`dashboard.js:1393`) regardless of live row count. Claims `+ Batch Approve (0)` (`dashboard.html:2191`) is a hardcoded zero that never reflects the pending count.
10. **Sidebar covers 6 of 10+ views.** `dashboard.html:30-75` exposes dashboard / employee-directory / attendance-daily / claims / messages / logs. `employee-manage`, `employee-grievance`, `attendance-shift`, `attendance-leave` are reachable only via tab pills; `reports`/`profile`/`my-details` exist only in `viewBreadcrumbs` (`dashboard.js:90-104`). Tour stops for those hidden views still work (panel ids exist), but a user following the tour cannot re-navigate to them from the sidebar afterwards.

## Honesty violations

Scope note: T8 + issue-146 fixes already made the failure paths honest (demo fallback + `API unreachable — showing demo data` toasts on summary/directory/attendance/roster/payroll/audit, `dashboard.js:1476,1540,1598,1631,1691,1729`). What remains is **toast-only success claims on controls that persist nothing**, plus a few stale disclosures:

- **Roster assign/remove toasts claim persistence (DOM-only).** `confirmAddStaff` appends a local row, flips the badge to `Draft`, recomputes coverage, then `showToast('Assigned ${name} … successfully!')` (`dashboard.js:735-784`) — no `POST /api/shift-rosters/` exists anywhere in the file. `removeShiftStaff` → `showToast('Employee removed from shift slot.')` (`dashboard.js:786-811`) likewise. `handleShiftDateChange` → `showToast('Roster updated for …')` (`dashboard.js:676-688`) on a date-picker change with no write. And `+ Assign …` on the roster header is `onclick="showToast('Roster assignment dialog ready.')"` (`dashboard.html:1532`) — it opens nothing. Minimum honest fix: label these "draft preview — not saved" or wire the POST.
- **Promote/Transfer record buttons claim success.** `onclick="showToast('Promotion recorded successfully!')"` (`dashboard.html:889`) and `onclick="showToast('Transfer recorded successfully!')"` (`dashboard.html:945`) fire on buttons whose forms have no submit handler (commit `2ba7d53` intended an honest disabled state — verify the stylesheet actually dims them; the static HTML still fires a success toast on click).
- **Exit-document uploads claim dialogs that don't exist.** `showToast('Upload dialog opened for …')` ×4 (`dashboard.html:1067-1088`) and the onboarding equivalents ×5 (`dashboard.html:3592-3622`) plus `Re-upload dialog opened` (`dashboard.html:3633`); the ✕ "remove" spans only dim opacity then toast `File removed`/`Contract removed` (`dashboard.html:1099,3631`).
