Why this is decoupled (panel-ready wording)

  • Replaceable client: any HTTP client (the planned mobile app, scripts via token) consumes the same 58 routes; the dashboard holds no business logic.
  • Auth at the edge: split HR/employee doors, ownership scoping, and throttles execute before any business code.
  • Swappable storage: one environment variable moves the system from file SQLite to hosted Postgres; no code path names an engine.
  • Server-side identity: Supabase keys and Auth calls exist only in core/supabase_client.py and views; a client swap cannot leak them.
  • Event side-effects: audit, notifications, and auto-allocation fire via signals — views stay unaware of them.
  • Offline ops: purge and import run as commands/endpoints outside the request cycle with dry-run previews.
